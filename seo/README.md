# هستهٔ SEO سیتارو

همهٔ متاهای عمومی در `seo/templates/seo/_meta.html` و داده‌های آن‌ها در `seo/services.py` ساخته می‌شوند. این بخش هیچ API خارجی، امتیاز ذخیره‌شده یا `meta keywords` ندارد. چک‌لیست ادمین توصیهٔ تحریریه است، نه پیش‌بینی رتبهٔ گوگل.

## مدل‌ها و مسیرهای ادمین

- پست بلاگ: `/admin/blog/post/` — عنوان، محتوا، تصویر، زمان ساخت و ویرایش از مدل موجود؛ فیلدهای SEO از `SEOFieldsMixin`.
- نمونه‌کار: `/admin/portfolio/project/` — عنوان، خلاصه، تصویر و alt موجود حفظ شده‌اند؛ `meta_title` قدیمی در migration به `seo_title` کپی شده و دادهٔ اصلی حذف نشده است.
- ابزار: `/admin/tools/tool/` — فیلدهای SEO در مدل موجود، اما فقط ابزار فعال با صفحهٔ مستقلِ واقعی متای مخصوص و Schema می‌گیرد. ابزارهای «به‌زودی» و مسیر redirect عمومی Schema صفحهٔ ابزار نمی‌گیرند.
- صفحات ثابت: `/admin/seo/staticpageseo/` — `home`، `contact`، `tools`، `portfolio_index` و `blog_index`. هر کلید فقط یک رکورد می‌پذیرد.
- تنظیمات سایت: `/admin/seo/siteseosettings/` — یک رکورد برای نام، URL، پیش‌فرض‌ها و داده‌های واقعی سازمان.

## ترتیب fallback

- عنوان محتوا: `seo_title` ← عنوان/نام مدل ← عنوان پیش‌فرض سایت. برای پروژه، `meta_title` قدیمی نیز تا زمان پاک‌سازی داده، قبل از عنوان مدل fallback است.
- توضیح: `meta_description` ← `summary`/`short_description` ← خلاصهٔ امن `content`/`introduction` ← توضیح پیش‌فرض سایت.
- canonical: مقدار اختصاصی معتبر ← `get_absolute_url()` محتوا ← URL صفحه ثابت بر اساس route. مبنای دامنه از تنظیمات سایت می‌آید.
- تصویر اجتماعی: `og_image` ← `cover` ← `default_og_image`.
- صفحات ثابت بدون رکورد SEO از متن‌های پیش‌فرض همان route استفاده می‌کنند. صفحهٔ اصلی از عنوان و توضیح پیش‌فرض تنظیمات سایت استفاده می‌کند.
- صفحات ورود و پنل کاربری `noindex, nofollow` هستند.

Schema خودکار فقط دادهٔ واقعی را استفاده می‌کند: `BlogPosting` برای پست، `BreadcrumbList` و در صورت دادهٔ کافی `CreativeWork` برای نمونه‌کار، و `WebApplication` برای ابزار فعال با صفحهٔ مستقل. `Organization` و `WebSite` از رکورد تنظیمات سایت فقط در صفحهٔ اصلی رندر می‌شوند. حالت `custom` فقط JSON-LD اعتبارسنجی‌شدهٔ همان صفحه را می‌گذارد و حالت `disabled` هیچ Schema مخصوص صفحه تولید نمی‌کند. `noindex` نیز Schema را حذف می‌کند.

## چک‌لیست دستی

1. یک پست بلاگ با عنوان/توضیح SEO و تصویر بسازید. در سورس صفحه دقیقاً یک title، description، canonical، robots و JSON-LD معتبر ببینید؛ عنوان و توضیح اختصاصی را پاک کنید و fallback را بررسی کنید.
2. یک نمونه‌کار منتشرشده را باز کنید. تصویر و alt، breadcrumb واقعی، `CreativeWork` بدون rating/review و canonical را بررسی کنید. با `robots_index=False` نبود Schema را کنترل کنید.
3. یک ابزار فعال دارای صفحهٔ مستقل را باز کنید و متای اختصاصی‌اش را ببینید. یک ابزار «به‌زودی» یا غیرفعال نباید صفحه یا Schema جزئیات قابل ایندکس داشته باشد.
4. صفحهٔ تماس و فهرست‌ها را با و بدون رکورد `StaticPageSEO` بررسی کنید. برای یک صفحه `noindex` بگذارید و حذف آن از sitemap را بررسی کنید.
5. در ادمین یک `custom_schema` نامعتبر وارد کنید؛ باید خطای فارسی بگیرید. نمونهٔ معتبر را ذخیره و خروجی JSON-LD را بررسی کنید.
6. در تنظیمات سایت نام/URL/لوگو/شبکه‌های اجتماعی را فقط با اطلاعات واقعی تکمیل کنید. Schema سازمان و سایت را در صفحهٔ اصلی اعتبارسنجی کنید.
